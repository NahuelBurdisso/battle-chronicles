# Battle Chronicles - the opening of a battle.
#
# THIS FILE ONCE HELD A SECOND, HIDDEN `scope = combat` EVENT ON on_combat_start,
# AND IT IS GONE FOR A MEASURED REASON. Over 22 qualifying combats it fired 22
# times, its `every_combat_side` ran 44 times - exactly two sides per combat, so
# the scope and the iteration both worked - and `side_commander` produced a
# commander ZERO times. The same link reached a commander 227 times in the same
# session from mid-battle call sites. NO COMMANDER IS ASSIGNED TO A COMBAT SIDE
# AT on_combat_start. No routing fixes that, so the opening moved into the battle:
# it is raised from the end of bc_battle_open_effect, on the battle's first
# moment. See bc_eve_effects.txt.
#
# That also re-explains the older DIAG Q2 finding recorded in the README -
# `combat_attacker` / `combat_defender` were very likely never the problem; there
# was simply nobody there to find.
#
# GENERAL LESSON, KEPT BECAUSE IT COST TWO RUNS: a `?=` block that never runs is
# indistinguishable from one that had nothing to do. Every speculative scope link
# in this mod ships behind its own debug_log for exactly that reason.

# ---------------------------------------------------------------------------
# The opening, as the player sees it. A character_event on the commander.
#
# THE ONLY MOMENT IN THE MOD WHERE THE PLAYER COMMITS AHEAD OF KNOWING ANYTHING.
# Every other choice answers something that has already happened. This one is
# taken as the lines form - on the first moment of the battle, before any of it
# has resolved.
#
# FOUR OPTIONS APPLY A FAMILY-2 MODIFIER BY NAME, and these are the only call
# sites in the mod that do. Everywhere else the (KIND, SWING) table inside
# bc_record_moment_effect decides which modifier a moment implies. There is no
# moment here - nothing has happened yet - so there is no seam call to route
# through and the option names the posture directly. It still goes through
# bc_add_verb_effect rather than add_character_modifier, so the 20-day duration
# stays in one place per family.
#
# NO OPTION APPLIES MOMENTUM. The battle has not started. The eve is about shape,
# not advantage, and momentum is the tide.
#
# THE THIRD OPTION IS NOT FREE. Declining to commit is a choice, and a commander
# who never commits should not be indistinguishable from one who does.
# ---------------------------------------------------------------------------

	# preached is a war the man commanding does not lie awake over. A zealot
	# takes this and a cynic takes a, and the modifier they get is the same.
	#
	# THE FAITH COMPARISON IS COPIED FROM bc_write_bond_effect'S `heathen` ARM
	# so the eve and the bond clause cannot disagree about who is a heathen:
	# `scope:X = { NOT = { faith = <subject>.faith } }`, the foe's scope
	# entered and the subject's faith read from outside it. Written the other
	# way round it would still compile and would still be right, but the two
	# places would have to be re-read together to see that.
	#
	# NESTED, NOT SIBLING, on the scope read, the same idiom as g above.
	option = {
		name = bc_chronicles.0011.h
		trigger = {
			exists = scope:bc_eve_foe
			trigger_if = {
				limit = { exists = scope:bc_eve_foe }
				scope:bc_eve_foe = { NOT = { faith = root.faith } }
			}
		}
		bc_add_verb_effect = { MODIFIER = bc_bloodied }
		add_piety = 50
		debug_log = "BC: eve option heathen"
	}

	# THE WINTER BAND, WHICH WAS THE LAST OF THE SIX WITH NO OPTION OF ITS OWN.
	# d takes rough, forest and jungle; f takes open and desert; winter fell
	# between them and f's header says why - its paragraph is about what the day
	# is doing to the men, which is neither a thing to hold nor a road to ride
	# down. So this option is not about the ground at all. It is about the men
	# standing on it before anything has started.
	#
	# THE ONLY OPTION IN THE MOD THAT COSTS GOLD, AND THE ONLY ONE WITH A
	# RESOURCE GATE. Every other eve option is paid for in stress, prestige or
	# piety, all of which a landless knight has as much of as a king. Coin is
	# the one currency that can be absent, so the trigger asks for it - an
	# option that offers a purchase the player cannot afford is worse than one
	# that is not shown, which is the same argument the file header makes about
	# greying out d on a plain.
	#
	# `remove_short_term_gold`, NOT `add_gold = -100`. The negative form throws
	# a script error; the mod's other paid option, bc_chronicles.0001.e, uses
	# the same call for the same reason.
	#
	# IT GRANTS bc_bloodied, WHICH a AND h ALSO GRANT, and that is the pattern
	# those two established: the modifier is not what separates eve options, the
	# coin is. a pays 10 stress, h pays 50 piety, this pays 100 gold. What is
	# bought is the same posture - men who have been given fires and the last of
	# the wine before dawn hit harder and hold worse, which is precisely
	# bc_bloodied's trade.
	#
	# NESTED, NOT SIBLING, on the ground read, the same idiom as d, f and g. The
	# gold test is a plain root read and needs no wrapper.
	option = {
		name = bc_chronicles.0011.i
		trigger = {
			gold >= 100
			exists = scope:bc_eve_ground
			trigger_if = {
				limit = { exists = scope:bc_eve_ground }
				scope:bc_eve_ground = { bc_ground_is_winter_trigger = yes }
			}
		}
		remove_short_term_gold = 100
		bc_add_verb_effect = { MODIFIER = bc_bloodied }
		debug_log = "BC: eve option winter"
	}
