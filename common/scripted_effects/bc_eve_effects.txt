# Battle Chronicles - the opening.
#
# THIS EFFECT ONCE RAN FROM `scope = combat` ON on_combat_start. IT DOES NOT ANY
# MORE, AND THE REASON IS MEASURED. Over 22 qualifying combats the old route
# logged `BC: eve fired` 22 times and `BC: eve side` 44 times - exactly two sides
# per combat, so both the `scope = combat` event and `every_combat_side` worked -
# while `BC: eve commander` logged ZERO. side_commander returned nothing for all
# 44 sides.
#
# THAT IS NOT A BROKEN SCOPE LINK. The same `side_commander` reached a commander
# 227 times in the same session through the mod's verb markers. The difference is
# WHEN: at on_combat_start no commander is assigned to a side yet. This also
# re-explains DIAG Q2 - `combat_attacker` / `combat_defender` were very likely
# never the problem either; there was simply nobody there to find.
#
# NOTHING CAN FIX THIS BY ROUTING. There is no pre-battle hook other than
# on_combat_start in the on_action dump, and no route reaches a commander who does
# not exist yet. So the opening moved INTO the battle.
#
# CALLED FROM THE END OF bc_battle_open_effect, WHICH IS WHY IT NEEDS NO
# PARAMETERS AND NO ITERATION. That effect is already the one place the mod
# guarantees an effect runs on the side commander during a battle - its own
# comment says so - and it has already, above the call site:
#   - saved and validated the enemy commander into var:bc_battle_foe
#   - set var:bc_battle_size in all three branches
# So the foe and the size are both simply there.
#
# THE FIRST-MOMENT TEST IS `NOT = { exists = var:bc_battle_moments }`. This is the
# same idiom plan 2's cooldown floor uses. bc_battle_open_effect runs on EVERY
# moment of a battle, but bc_record_moment_effect - the only writer of
# bc_battle_moments - runs immediately AFTER it at every call site, so on the
# first moment of a battle the variable does not exist yet and on every later
# moment it does. That makes this "once per battle" without a new scratch variable.
#
# var:bc_battle_size IS READ BARE, AND ONLY HERE. Every other size gate in the mod
# nests the read behind `exists` because its call sites can run after
# bc_clear_scratch_effect. This one cannot: the write is forty lines above, in the
# same effect, on a path with no branch that skips it. Nesting here would be
# guarding against something that cannot happen.
#
# THE FOE COMES FROM var:bc_battle_foe, NOT scope:bc_open_foe. The variable is
# MAINTAINED - bc_battle_open_effect's else arm removes it when the enemy side
# is leaderless - while the scope is written on one arm only and cleared on
# neither. So on a leaderless side scope:bc_open_foe is either absent or stale,
# and reading it would either read nothing or name the wrong man in the nemesis
# line. The variable is the one with a defined value on every path.
#
# SCOPE LIFETIME IS UNVERIFIED HERE, and this comment does not depend on it.
# Whether a saved scope survives past the event execution that wrote it is not
# in the 1.19.0.6 script_docs dump and cannot be settled by reading files; the
# usual reading is that `save_scope_as` writes into the CURRENT execution's
# scope list and `trigger_event` copies that list into the raised event, which
# would mean a scope cannot leak from one battle into the next at all. Every
# scope read in this file is `exists`-guarded, so both readings are safe. Do
# not spend a session closing a cross-battle leak until a run has shown one.
#
# bc_eve_foe IS SAVED INSIDE THE is_ai = no GATE. Kept from the original for the
# same reason it was written: it costs nothing and it keeps the save off every AI
# commander in the world.
#
# THE COOLDOWN IS TAKEN BEFORE THE EVENT IS RAISED, not in the event. An event
# raised on a character is not guaranteed to have been answered - or even opened -
# by the time anything else runs, and the throttle is about how often the mod
# INTERRUPTS, not about how often the player replies.
#
# NOT bc_can_interrupt_player_trigger. That trigger tests bc_popup_cooldown, which
# is the mid-battle budget the opening must not spend. The two rows are written
# out here so that the two throttles cannot be accidentally merged later.
bc_eve_offer_effect = {
	if = {
		limit = {
			is_ai = no
			NOT = { has_character_flag = bc_eve_cooldown }
			NOT = { exists = var:bc_battle_moments }
			var:bc_battle_size >= 3
		}
		if = {
			limit = { exists = var:bc_battle_foe }
			var:bc_battle_foe = { save_scope_as = bc_eve_foe }
		}

		# THE EVE READS SCOPES, NOT SCRATCH, and this is the reason. The pop-up
		# is a player event sitting in a queue; its desc renders when the player
		# gets round to it, which can be after the combat has ended and
		# bc_clear_scratch_effect has run. A saved scope is not cleared. The
		# freshness comes from writing it here, one line before the raise; the
		# durability comes from it being a scope.
		#
		# THE HOLE, IF SCOPES OUTLIVE THEIR EXECUTION - see the SCOPE LIFETIME
		# note at the top of this file, which says that is UNVERIFIED and quite
		# possibly false. If they do: a player who leaves one eve unanswered
		# and is offered another renders the second against the first's ground,
		# and the same goes for scope:bc_eve_foe, whose `if` above does not
		# fire on a leaderless enemy side. If they do not, both simply come up
		# absent and the guarded fallbacks render, which is correct behaviour.
		#
		# WHY IT IS WORTH WATCHING EITHER WAY: bc_eve_foe drives four desc arms
		# — nemesis, kin, heathen, countryman — and the nemesis one is shared
		# with option e, because bc_eve_facing_nemesis_trigger reads
		# scope:bc_eve_foe and gates both. A stale foe who happened to be the
		# nemesis would render the nemesis paragraph AND unlock option e, which
		# grants bc_bloodied and 5 stress to a real character. That is the only
		# path in the eve where a wrong scope does something rather than
		# showing something. In the log it looks like `BC: eve ground missing`
		# counting while `BC: eve offered` counts more.
		if = {
			limit = { exists = scope:combat_side.combat.location }
			scope:combat_side.combat.location = { save_scope_as = bc_eve_ground }
		}
		else = {
			debug_log = "BC: eve ground missing"
		}
		bc_start_eve_cooldown_effect = yes
		debug_log = "BC: eve offered"
		trigger_event = bc_chronicles.0011
	}
}
